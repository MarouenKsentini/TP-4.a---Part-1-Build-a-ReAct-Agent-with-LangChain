Objectives

  1. Wrap a vector retriever (Chroma) into a LangChain tool the LLM can call.
  2. Plug in two external tools: Tavily web search and arXiv.
  3. Write a system prompt defining role, routing rules and guardrails.
  4. Create a ReAct agent and run it with an anti-loop limit.
  5. Trace every Action → Observation → Final answer step and measure tools, latency and step count.
  6. Evaluate the agent on a 5-question golden set and draw reasoned conclusions.

The ReAct principle

ReAct (Reasoning + Acting) alternates three phases: the model reasons (Thought), acts by calling a tool (Action), then reads the tool result (Observation). The loop repeats while the model thinks it lacks information, and stops when it produces a final answer.

Key pointEarly LangChain versions implemented ReAct as a text format (Thought:, Action:, Observation:) that had to be parsed, which was fragile. Today LLMs natively expose structured tool_calls (JSON). The agent here uses that mechanism: no text parsing, same loop logic.

We recreate a mini-corpus of 4 documents (Transformer, RAG, vector databases, fine-tuning), split it, compute embeddings and index it in Chroma.

First runThe first execution downloads the all-MiniLM-L6-v2 model (~90 MB) from Hugging Face and caches it, so it can take a minute. uv also installs PyTorch as a dependency of sentence-transformers, which is a large download the first time (uv caches it for later projects).

The indexing pipeline in 3 stages

  1. Corpus: the CORPUS dict maps a filename to its Markdown text. Each entry becomes a Document with a source metadata field, which lets the agent cite sources.
  2. Splitting: from_tiktoken_encoder cuts into 300-token chunks with 30-token overlap. The texts are short, so each document fits in one chunk: 4 documents → 4 chunks.
  3. Indexing: all-MiniLM-L6-v2 (384 dimensions, runs locally) vectorises each chunk; Chroma stores them; as_retriever(k=4) returns the 4 nearest chunks for a query.
Key pointWith only 4 chunks and k=4, the retriever returns the entire corpus on every query; only the order changes. Fine for a lab, but in production keep k small relative to corpus size.

Step 1 - Turn the retriever into a tool

An LLM cannot call a Python object. It can call a tool described by a name, a description and a function. We wrap the retriever.

Cell 4 - rag_search tool
from langchain_core.tools import Tool

def _rag_search(query: str) -> str:
    docs = retriever.invoke(query)
    if not docs:
        return "[Aucun document pertinent trouvé dans le corpus local]"
    return "\n\n---\n\n".join(
        f"[source: {d.metadata.get('source', '?')}]\n{d.page_content}"
        for d in docs
    )

rag_tool = Tool(
    name="rag_search",
    description=(
        "Cherche des informations dans le corpus IA local (Transformer, RAG, "
        "fine-tuning, vector databases). À utiliser pour les questions techniques "
        "sur ces sujets quand l'information est susceptible d'être dans la base."
    ),
    func=_rag_search,
)

# Quick test
print(rag_tool.invoke("How does HNSW work?")[:400])

  • _rag_search calls the retriever and formats results as text: each chunk is prefixed with [source: ...] and separated by ---, giving the LLM a readable, traceable context.
  • Empty case: it returns an explicit message rather than an empty string, so the LLM understands it should look elsewhere.
  • Tool(name, description, func): name and description are sent to the LLM, which decides from the description whether to use the tool.
  • The isolated test confirms the first chunk is vector_databases.md before handing the tool to the agent.
TipA tool description is a prompt. A vague one ("search for info") produces random routing; a precise one (topics covered + use case) steers the LLM to the right tool.

Agent ReAct (LangGraph prebuilt) prêt avec 3 outils.
stderr warningLangGraphDeprecatedSinceV10: create_react_agent has been moved to langchain.agents. Please update your import to from langchain.agents import create_agent. It remains usable until LangGraph 2.0.
  • temperature=0 makes the agent's decisions as deterministic as possible, essential for comparing runs.
  • create_react_agent(llm, tools, prompt=...) builds a compiled LangGraph with two nodes: agent (the LLM) and tools (the tool executor). The LLM receives tool schemas via bind_tools.
  • It is no longer an AgentExecutor: call invoke({"messages": [...]}) and get the full message history back.

What happens inside

  1. The agent node sends the LLM: system prompt + history + tool schemas.
  2. If the reply contains tool_calls, the graph moves to tools, which runs each call and appends a ToolMessage.
  3. Back to agent with the observation injected: this is the ReAct loop.
  4. If the reply has no tool_call, the graph stops: that is the final answer.

Step 6 - Instrumented execution function

We do not call the bare agent: we wrap it in a function that times the run, extracts the tools called, finds the final answer and prints the ReAct trace.

Cell 9 - run_react_agent
def run_react_agent(question: str) -> dict:
    """Run the ReAct agent (LangGraph prebuilt) and capture trace + metrics.

    LangGraph output: result["messages"] = ordered list
    [HumanMessage, AIMessage(tool_calls=...), ToolMessage, ..., AIMessage final].
    """
    if not GROQ_OK:
        return {"answer": "[Pas de clé Groq]", "tools_used": [], "steps": 0, "duration_s": 0}

    t0 = time.time()
    try:
        result = agent_executor.invoke(
            {"messages": [("user", question)]},
            {"recursion_limit": 12},      # anti-loop guardrail
        )
        duration = time.time() - t0
        messages = result["messages"]

        # Tools called (from AIMessages carrying tool_calls)
        tools_used = []
        for msg in messages:
            for tc in getattr(msg, "tool_calls", []) or []:
                tools_used.append(tc["name"])

        # Final answer = last non-empty AIMessage
        final_answer = ""
        for msg in reversed(messages):
            if msg.__class__.__name__ == "AIMessage" and getattr(msg, "content", ""):
                final_answer = msg.content
                break

        # Verbose ReAct-style display
        for msg in messages:
            cls = msg.__class__.__name__
            if cls == "AIMessage":
                if msg.tool_calls:
                    for tc in msg.tool_calls:
                        print(f"  🤖 Action : {tc['name']}({tc['args']})")
                elif msg.content:
                    print(f"  💬 Final : {msg.content[:200]}{'…' if len(msg.content) > 200 else ''}")
            elif cls == "ToolMessage":
                preview = str(msg.content)[:160].replace("\n", " ")
                print(f"  📥 Observation [{msg.name}] : {preview}…")

        return {
            "answer": final_answer,
            "tools_used": tools_used,
            "steps": len(tools_used),
            "duration_s": round(duration, 2),
        }
    except Exception as e:
        return {"answer": f"[Erreur : {e}]", "tools_used": [], "steps": 0,
                "duration_s": round(time.time() - t0, 2)}
BlockRole
if not GROQ_OK guardReturns a neutral result instead of calling the API without a key
invoke(..., {"recursion_limit": 12})Runs the loop; beyond 12 graph super-steps LangGraph raises an error (anti-loop guardrail)
tools_used extractionWalks AIMessages and collects each tool_call name
final_answer searchWalks messages backwards, takes the last non-empty AIMessage
Trace display🤖 Action (tool call) · 📥 Observation (ToolMessage, cut at 160 chars) · 💬 Final (cut at 200 chars)
except ExceptionCatches any error (quota, network...) so the golden-set loop keeps going
Key pointThe whole ReAct trace is rebuilt from a single list: result["messages"].

How to read a trace

  • 🤖 Action: the tool chosen and the arguments generated. This is where you judge query quality.
  • 📥 Observation: start of what the tool returned. Check that it is relevant.
  • 💬 Final: the final answer. Compare it with the observation: is it faithful to the sources?
  • 📊 Summary line: tools used, duration, step count.

Lessons

  1. An agent can fail silently (Q1). The simplest question, fully covered by the corpus, produced zero tools and an empty answer with no exception. The LLM probably returned an empty message or a malformed tool call. Without explicit checks, this goes unnoticed in production.
  2. Picking the right tool is not enough (Q2, Q3). In Q3 the agent chose arxiv_search but generated LoRA 2021 parametric efficiency fine-tuning; arXiv returned recent derivative papers. An exact-title query (LoRA: Low-Rank Adaptation of Large Language Models) or an author query would have found the paper. To its credit the agent honestly admitted not finding it, but did not retry.
  3. Multi-hop is not guaranteed (Q4). The prompt says to use rag_search first for HNSW, yet the agent went straight to the web. Prompt rules are suggestions the LLM may ignore.
  4. Out-of-domain refusal works (Q5). When a rule is simple and unambiguous the LLM follows it: immediate refusal at no tool cost (0.81 s).
Part 1 conclusionA pure ReAct agent has no self-evaluation mechanism. It checks neither the relevance of retrieved documents nor the faithfulness of its answer, and does not automatically switch source on failure. Part 3 (LangGraph) fixes this with developer-enforced grade_docs and grade_answer nodes, query rewrite and a web_search fallback.

Exercise 1 - Detect the silent failure

Modify run_react_agent so an empty final answer triggers a retry (at most 2 attempts), then returns "[Aucune réponse produite]" if it still fails. Re-run Q1.

Solution sketch
Python
def run_react_agent(question: str) -> dict:
    if not GROQ_OK:
        return {"answer": "[Pas de clé Groq]", "tools_used": [], "steps": 0, "duration_s": 0}
    t0 = time.time()
    final_answer, tools_used, messages = "", [], []
    try:
        for tentative in range(2):
            result = agent_executor.invoke(
                {"messages": [("user", question)]},
                {"recursion_limit": 12},
            )
            messages = result["messages"]
            tools_used = [tc["name"] for m in messages
                          for tc in (getattr(m, "tool_calls", []) or [])]
            final_answer = ""
            for m in reversed(messages):
                if m.__class__.__name__ == "AIMessage" and getattr(m, "content", ""):
                    final_answer = m.content
                    break
            if final_answer.strip():
                break
            print(f"  ⚠ Réponse vide (tentative {tentative + 1}/2)")
        if not final_answer.strip():
            final_answer = "[Aucune réponse produite]"
        # (keep the trace-printing loop from Cell 9 here)
        return {"answer": final_answer, "tools_used": tools_used,
                "steps": len(tools_used), "duration_s": round(time.time() - t0, 2)}
    except Exception as e:
        return {"answer": f"[Erreur : {e}]", "tools_used": [], "steps": 0,
                "duration_s": round(time.time() - t0, 2)}

Exercise 3 - Measure routing automatically

Write routing_score(golden_set, react_results) that compares expected_tools with tools_used and returns exact, partial or wrong per question, plus a global score.

Solution sketch
Python
def routing_score(golden_set, react_results):
    points = {"exact": 1.0, "partiel": 0.5, "faux": 0.0}
    per_q, total = {}, 0.0
    for item in golden_set:
        exp = set(item["expected_tools"])
        got = set(react_results[item["id"]]["tools_used"])
        if exp == got:
            verdict = "exact"
        elif exp and got and (exp & got):
            verdict = "partiel"
        else:
            verdict = "faux"
        per_q[item["id"]] = verdict
        total += points[verdict]
    return per_q, round(total / len(golden_set), 2)

per_q, score = routing_score(golden_set, react_results)
print(per_q, "→ score global :", score)
On the course run this gives Q1 faux, Q2 exact, Q3 exact, Q4 partiel, Q5 exact, global 0.7.
